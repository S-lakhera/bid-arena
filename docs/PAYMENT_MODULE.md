# Payment Module Documentation (Razorpay Integration)

This document outlines the architecture, flow, and usage of the Payment Module implemented in the BidArena backend using Razorpay.

## Overview

The payment module handles the checkout process for the winner of a completed auction. It ensures that only the rightful winner can initiate the payment and securely verifies the transaction using Razorpay's HMAC SHA256 signature verification.

## Dependencies

- **razorpay**: The official Node.js SDK for Razorpay.
- **crypto**: Native Node.js module used to verify webhooks/signatures.
- **zod**: Used for payload validation on the verify endpoint.

## Environment Variables

The following environment variables must be configured in your `.env` file:

```env
RAZORPAY_KEY_ID=your_razorpay_key_id
RAZORPAY_KEY_SECRET=your_razorpay_key_secret
```

## Database Schema Changes (`Auction Model`)

Two new fields were added to the `Auction` schema to track payments:

1. `paymentStatus`: Enum `["pending", "paid", "failed"]`. Defaults to `"pending"`.
2. `razorpayOrderId`: String to store the unique order ID generated by Razorpay.

## Architecture & Components

### 1. Payment Service (`src/services/payment.service.js`)

Abstracts the Razorpay logic to keep the controllers clean.

- **`createRazorpayOrder(amount, receiptId)`**: Initializes a new order in Razorpay. Note: Razorpay accepts amounts in paise (INR \* 100).
- **`verifySignature(orderId, paymentId, signature)`**: Generates an HMAC SHA256 hash using `orderId | paymentId` and the `RAZORPAY_KEY_SECRET`, and compares it to the incoming signature to prevent spoofing.

### 2. Validation (`src/validations/payment.validation.js`)

A Zod schema `verifyPaymentSchema` ensures that the verification endpoint strictly receives:

- `razorpay_order_id`
- `razorpay_payment_id`
- `razorpay_signature`

### 3. Payment Controller (`src/controllers/payment.controller.js`)

- **`createCheckoutSession`**:
  - Validates the auction is `completed` and not already `paid`.
  - Ensures the user requesting is the actual `winner`.
  - Generates the Razorpay order and saves the `order.id` to the database.
- **`verifyPayment`**:
  - Validates the Razorpay signature using the Payment Service.
  - Updates the auction's `paymentStatus` to `"paid"`.
  - Creates a `payment_success` log in the `Timeline`.
  - Emits a `payment-success` Socket.io event to the specific auction room.

## API Endpoints

### 1. Create Order

Creates a Razorpay order for the completed auction.

- **URL**: `POST /api/v1/payments/create-order/:auctionId`
- **Access**: Protected (Bearer Token Required)
- **Response**: `201 Created`
  ```json
  {
    "success": true,
    "message": "Order created successfully",
    "data": {
      "id": "order_XXXXXXXX",
      "amount": 500000,
      "currency": "INR",
      "receipt": "64abcdef1234567890"
    }
  }
  ```

### 2. Verify Payment

Verifies the payment after the frontend checkout is complete.

- **URL**: `POST /api/v1/payments/verify`
- **Access**: Protected (Bearer Token Required)
- **Body**:
  ```json
  {
    "razorpay_order_id": "order_XXXXXXXX",
    "razorpay_payment_id": "pay_XXXXXXXX",
    "razorpay_signature": "a1b2c3d4e5f6..."
  }
  ```
- **Response**: `200 OK`
  ```json
  {
    "success": true,
    "message": "Payment verified successfully"
  }
  ```

## Frontend Integration Flow

1. **Initiate**: The winner clicks "Pay Now" on a completed auction.
2. **Order Creation**: Frontend hits `POST /api/v1/payments/create-order/:auctionId`.
3. **Checkout Modal**: Frontend initializes the Razorpay checkout script using the `order.id` and `amount` returned from the API.
4. **Success Callback**: Upon successful card entry, the Razorpay modal's `handler` function receives the `payment_id`, `order_id`, and `signature`.
5. **Verification**: Frontend sends those 3 fields to `POST /api/v1/payments/verify`.
6. **Socket Broadcast**: The backend verifies, updates the DB, and emits the `payment-success` socket event so all users on the page instantly see the auction is paid!
